# ADR: isolated Worker authentication feasibility slice

Status: accepted engineering boundary for [ticket #70](https://github.com/rudeayelo/aimharder-mcp/issues/70), observed locally on 2026-10-18. Complements the [runtime candidate](2026-10-16-proposed-cloudflare-hosted-runtime.md); does not replace its full pilot acceptance requirements or authorize deployment.

## Context

The maintained Better Auth MCP plugin 1.7.10 documents SDK v2 and a stateless 2026-07-28 protocol profile. The existing local package pins SDK v1 and already supports eighteen tools. Replacing that distribution or extending the full portal before proving Worker authentication would enlarge the initial gate unnecessarily.

## Decision

Keep `hosted/` as a private package with its own pinned dependencies and lockfile. Use Better Auth 1.7.10 with its maintained JWT/MCP components, D1 schema generated by its migration API, SDK v2 2.3.1, and the workerd/Miniflare combination pinned by Wrangler 4.151.1. Exercise one read-only account-context path against the existing independent AimHarder API client. Keep the public local package and SDK v1 unchanged except for the minimal Fetch redirect portability correction.

Resolve account configuration only from the verified OAuth subject through a connection-provider boundary. The feasibility harness supplies synthetic configuration; the production entry returns an unconnected state until the later vault slice supplies it. Fixture identity/client setup is in a separately bundled test entry. At this local gate there was no deployed resource or production bootstrap API. The subsequent [isolated test-environment decision](2026-10-18-isolated-cloudflare-test-environment.md) authorizes and records a disabled-mail test deployment; it introduces no production bootstrap API.

Use the maintained default native scrypt implementation, not a custom reduced-work hash. Test real workerd execution, including hash creation, password sign-in, explicit client consent and PKCE exchange, and the SDK client over actual local HTTP. Configure the Workers-safe SDK schema validator. CI checks both local and hosted packages.

Keep dynamic registration disabled and CIMD absent for this slice. The synthetic client has an exact callback, PKCE and resource association. Unknown URL-shaped clients cannot initiate metadata fetches. The current CIMD network-safety contract requires DNS/address pinning with TLS identity preservation; ordinary Worker Fetch is not an established replacement. Later client integration must either demonstrate safe metadata transport or verify explicit provisioning with each actual client. Do not silently weaken that boundary.

## Consequences

The synthetic path demonstrates the selected released combination in a local Worker runtime. It does not establish live Cloudflare permissions, remote AimHarder connectivity, Google/email delivery, invitation admission, real-client compatibility, vault encryption or measured production costs. The [feasibility evidence](../hosted-feasibility.md) records pins, hash timing, safe metadata policy and the conditional 20-participant/EUR 10 envelope.

The tracer creates a client per call, so session reuse, authentication-failure state and preparations do not yet span remote calls. The later coordination ticket must replace this temporary boundary while preserving all existing capabilities and confirmation/uncertainty semantics. No action tool should be added using this temporary request-local state model.

SDK v2 legacy rejection is limited to this gate's documented profile; actual ChatGPT and Hermes protocol/authorization support remains an independent acceptance requirement. A material incompatibility or cost failure must leave the affected gate unresolved pending an explicit revised decision. The full scope, hosted credential-custody, administrator restrictions, retention and real-write consent decisions are unaffected.
