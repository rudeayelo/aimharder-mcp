# ADR: isolated Cloudflare test environment

Status: accepted engineering/operational boundary on 2026-10-18 after the user explicitly authorized creating the test environment without purchases or plan changes. Complements the [runtime candidate](2026-10-16-proposed-cloudflare-hosted-runtime.md), [feasibility gate](2026-10-18-isolated-worker-authentication-feasibility.md) and [invited admission decision](2026-10-18-invited-password-admission.md). It does not authorize a production launch or by itself complete #71's actual-delivery criterion; the later owner journeys are recorded separately below.

## Context

The local portal is implemented and tested against real Better Auth/D1 decisions with an external mail substitute. A read-only provider inspection established an active account-owned token/zone and limited resource reads, but subscription and Email Sending access returned HTTP 403. The user subsequently authorized an isolated test environment while explicitly excluding purchases and plan changes. A subsequent authenticated dashboard inspection established the current Workers plan as Free: 100,000 requests/day and 10ms CPU/request. The plan comparison shows Email Sending unavailable on Free and included on Paid, with Paid displayed as USD 5/month plus usage. No upgrade was selected. At that initial stage native email could not proceed under the no-purchases/no-plan-changes authorization and actual mailbox evidence was missing. The later Resend stage and owner acceptance below complete that delivery criterion.

Subsequent authorization: the owner supplied an existing Resend token for transactional mail without purchases or plan changes. The [Resend decision](2026-10-18-resend-transactional-delivery.md) replaces only the native-mail prerequisite; the owner later reported all three mailbox receipts, verified password login and successful recovery, completing #71 acceptance; Free CPU/load measurements remain pending. The absent-mail statements below describe the original anonymous deployment stage. Resend is now separately configured with verified domain/DNS and one provider-delivered owner invitation; the owner subsequently reported all three mailbox receipts, verified password login and successful recovery, as recorded in the linked replacement decision.

## Decision

Full-runtime amendment, 2026-10-19: the authorized test now runs reviewed production source 76686e4 with the same owner Worker, original application database and SQLite account namespace, plus the distinct independent recovery database/authority required by the [restoration decision](2026-10-19-independent-deletion-and-controlled-restoration.md). Preserve all protected mail/Google/vault configuration accepted in later stages. The [actual cutover record](../hosted-test-environment.md#full-runtime-activation-2026-10-19) documents frozen ingress, exact temporary-owner suspension, an actual old-queue response, once-applied migrations 0006–0009, closed production checks, genuine first epoch bootstrap, 12 bindings, canonical routing and helper retirement. Earlier unleased code was not treated as stopped merely because a deployment changed. No owner database restoration or synthetic recovery marker was used; the initial manual migration-ledger caveat remains. This extends the original one-database anonymous stage below without changing the test-only/no-purchase/no-plan-change boundary. Actual clients and sustainable capacity/cost remain #84 gates.

Use one dedicated Worker `aimharder-mcp-pilot-test`, one D1 `aimharder-mcp-pilot-test-auth`, and HTTPS custom origin `pilot-test.ahmcp.link`. Preserve existing scripts, DNS/routes and the root service origin. Deploy the production module bundle with compatibility date `2026-10-12` and `nodejs_compat`; use a fresh platform-secret `AUTH_SECRET`, fixed `BASE_URL` and the dedicated D1 only. Disable `workers.dev`, version preview URLs and Worker observability. Keep email, Google, owner bootstrap and upstream credentials absent while their acceptance prerequisites remain unresolved.

Pin official Wrangler 4.151.1 in the private package, matching the existing simulator dependency. Commit a standard manifest template containing no operational IDs/secrets; resolve IDs and absolute bundle/migration paths in a private configuration outside the checkout. Use ordinary Wrangler commands or equivalent official APIs with fresh read-back, without a custom deployment framework. Apply only the two committed migrations to the dedicated database. Operational credentials, upload metadata, IDs and real recipients stay outside repository/tracker/log output.

Validate the exposed anonymous surface through public HTTP with no accounts, cookies or real recipient data. Check real HTTPS separately. This proves remote routing and safe missing-sender outcomes, not password hashing within a Free CPU allowance, actual mailbox delivery, Google, ChatGPT/Hermes, upstream connectivity, isolation/lifecycle acceptance or measured cost. The earlier standard usage-model response did not establish a subscription plan; the later authenticated dashboard does establish the current Free plan. Neither anonymous HTTPS checks nor the 10ms displayed allowance proves maintained password hashing will work remotely. Any purchase, paid activation, plan change or broader permission grant needs precise separate approval; do not infer it from the environment authorization.

## Consequences

The isolated environment makes deployment/binding/schema/domain observations concrete without admitting participants or changing the local stdio distribution. Native default authentication remains maintained; no password or authorization policy changes are introduced by deployment setup. Retain safe disabled-mail behavior when configuration is absent. The later Resend activation and owner journeys complete #71; they do not establish the full hosted pilot or CPU/load/cost acceptance.

The [runbook and evidence](../hosted-test-environment.md) distinguish local dry-run/smoke results, remotely observed resource creation and still-unobserved stages. Provider API permission denials, the verified current Free plan and the resulting native-email blocker must remain explicit. The Paid planning envelope is not the account's current plan or authorization to upgrade. The preexisting authentication, credential-custody, write-confirmation and retention requirements continue unchanged; a test deployment cannot be presented as a complete hosted pilot.
