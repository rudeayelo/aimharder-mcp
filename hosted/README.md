# Hosted portal work

This private package contains the local Worker feasibility slice for [issue #70](https://github.com/rudeayelo/aimharder-mcp/issues/70) and the invited password portal's local implementation for [issue #71](https://github.com/rudeayelo/aimharder-mcp/issues/71), part of [the hosted specification](https://github.com/rudeayelo/aimharder-mcp/issues/69). It is not a deployed pilot or a complete portal. The current Workers plan is verified as Free; the user supplied an existing Resend token to replace native Email Sending without a plan change. The sending domain is verified and the dedicated Worker has Resend configured; the owner invitation is provider-confirmed delivered. Actual mailbox receipt, verified owner admission, recovery and deployed password-hashing behavior remain acceptance gates. #71 cannot be closed from synthetic checks.

From the repository root, install the local package with `pnpm install --frozen-lockfile`. Then, from this directory:

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm preview
```

CI runs the local and hosted checks separately. Root `pnpm test` covers the local package; this package's `pnpm test` runs the real workerd/D1 simulator and SDK v2 client. Both packages have separate lockfiles. The public npm package keeps SDK v1 and excludes `hosted/`.

The test harness bundles `tests/fixture-worker.ts` and `tests/portal-fixture-worker.ts` separately and provisions only synthetic identities, an exact registered callback, external email capture, and a synthetic account resolver. Every outbound request must match a synthetic boundary or the local authorization server. The build command bundles only `src/worker.ts`; it has no fixture provisioning/mail-inspection route, no account credentials, and no configured vault. Authenticated account queries therefore return a safe unconnected state until the later vault slice supplies `ResolveConnection`. No test credentials or generated auth tokens belong in a deployment configuration.

`AUTH_DB`, `AUTH_SECRET`, and `BASE_URL` are required runtime bindings. `AUTH_SECRET` belongs in platform secrets; the database binding must contain the maintained auth schema and admission migration. Enrollment, verification resend and recovery also require the `RESEND_API_KEY` platform secret and verified `MAIL_FROM`; without them they fail safely as unavailable. Ordinary tests do not contact the hosted domain or providers. The [isolated test setup](../docs/hosted-test-environment.md) uses pinned official Wrangler 4.151.1, `wrangler.test.example.jsonc` and a private resolved operator configuration outside the checkout; no operational IDs or active mail configuration belong in this template. `pnpm smoke:test-environment` is an explicit anonymous remote HTTP check. It defaults to the disabled-mail stage; set `HOSTED_SMOKE_MAIL_STAGE=configured` after enabling mail to omit all enrollment/recovery probes and keep the check free of mail side effects.

`migrations/0001-auth.sql` is generated by Better Auth 1.7.10's migration API against empty SQLite. `pnpm schema:generate` regenerates it for review; schema generation is not permission to apply a remote migration. Tests apply it only to disposable local D1. Future auth upgrades must review generated changes and migration/rollback behavior.

`migrations/0002-invitations.sql` stores application admission policy, distinct from the maintained auth schema. Apply both in order only in an authorized environment. `pnpm owner:prepare` creates private, offline owner-bootstrap artifacts outside the checkout and does not apply or send them. `pnpm preview` serves the production entry anonymously with disposable local state, no sender and external requests denied; use `PREVIEW_BASE_URL` with a Tailscale URL for a shared review. See [password portal setup, sender activation and acceptance](../docs/hosted-admission.md) for configuration, bootstrap, public routes and honest safe outcomes.

See [hosted feasibility evidence](../docs/hosted-feasibility.md) for dependency compatibility, metadata policy, hashing measurements, the conditional cost envelope, and the remaining acceptance stages.
